# Asset and Animation Request Template

**Specification package; no runtime or Drive changes.**

Every request names asset ID, encounter, object/control ID, visible purpose, required state variants, source/provenance, format, scale, coordinate convention, pivot and interaction proxy. If a dimension is not yet measured, keep the asset task open rather than invent precision.

A model request must show what part moves, its stable endpoints, blocking geometry and the clue that must remain visible. Animation records start trigger, logical committed state, projected motion, cancellation behavior and reduced-motion alternative. Materials must keep symbols legible in the room’s darkest supported state and in the reduced graphics fallback.

Audio requests identify exact trigger and meaning, source position, bus/volume control, duration/loop behavior, pause/unload behavior and caption. Do not assume an arbitrary audio/model format has a loader in the current provider. Any new decoder or format is a provider dependency.

All requested assets default to unproduced and unsourced. Before delivery attach actual file, rights evidence, performance/memory measurements and accepted integration screenshots. Until then, procedural proxy geometry must retain the same action and evidence.
