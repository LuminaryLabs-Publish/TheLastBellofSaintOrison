# Implementation Task Pack Template

**Specification package; no runtime or Drive changes.**

Each task names an observable outcome, exact input documents, source package, allowed file boundary, dependencies, procedure, acceptance and handoff. Assign a real owner only when known; unassigned is valid and must not be replaced with an invented collaborator.

Procedure should tell the contributor what to implement first, what existing contract to use, what result to inspect and which guard must stay intact. Link to a shared capability task if the required input/state/provider behavior is absent. Do not ask the room author to create an unreviewed local scheduler or mutate private resources.

Definition of done is specific: the player action is usable through supported input, produces the specified owner result and visible consequence, preserves branches/saves and passes the listed scenarios. A build success alone is insufficient.

Handoff records changed paths, exact source revision, evidence, unresolved failures, remaining asset requests and the next executable task. GitHub publication does not imply Google Drive synchronization or final creative approval.
