# Clue and Discovery Contract

**Target specification; runtime implementation pending.**

Investigation owns knowledge, observations, deductions and logical encounter progress. Presentation supplies the fact; an accepted operation records that it was exposed through a valid interaction. Merely entering a room or running its entry Sequence cannot grant all clues.

Each target encounter maps to existing source object IDs and required clue IDs. The current observation service derives the clue from its registered source object, not an arbitrary caller-provided clue string. Future physical inputs must preserve or explicitly extend those validated definitions. Do not pass a new TG-01 ID to an API expecting a room object ID.

A clue can be obtainable in several accessible ways: observed motion, a stepped diagram, or a faithful caption. These methods yield the same logical fact. Optional evidence remains separate from mandatory prerequisites. The ledger maps all 29 existing required clues to required encounters.

Duplicate observation does not add a second knowledge entry or item. Knowledge about a testimony is not proof the testimony is true. Corroborated identities retain their two independent sources and chosen aliases; four unverified names remain unverified.
