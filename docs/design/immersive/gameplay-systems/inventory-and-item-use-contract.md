# Inventory and Item Use Contract

**Target specification; runtime implementation pending.**

Inventory owns item identities and transformations. Current items are cassette, key, lantern, resin, protectedLantern, register, archive, relay, chalk and core. A location prop is not automatically a global inventory item.

Grant by stable item ID after the relevant completion condition. Use validates the target and required item before mutation. Wrong-target use explains the mismatch and consumes nothing. Combination validates both ingredients and yields the existing protectedLantern result; repeat requests cannot duplicate it. Do not replace the current recipe or inventory shape as part of documentation work.

Tethered tools, model badges and demonstration samples remain local mechanism controls. Their reset is part of the encounter, not an unlimited source of saleable/usable inventory. New permanent items require explicit schema, save, source-content and downstream dependency changes.

Source originals remain identifiable. Archive retrieval grants original proof; a photograph alone is not equivalent. Copies in the ascent and epilogue never remove originals or retroactively change ending eligibility. Snapshot owner state consistently with progress so a loaded latch cannot award another key.
