# The Last Bell of Saint Orison

A single-player psychological horror adventure built with NexusEngine. Mara Venn follows her missing sister's cassette into a town whose bell preserves erased identities. Investigate fifteen locations, keep a record of what you can prove, and choose Witness, Silence, or Vessel.

**Current delivery: a connected development build, with original first-pass procedural environments and synthesized audio.** It is not a Steam release or a verified three-hour/AAA-quality product. Read [delivery status](docs/validation/delivery-status.md) for the evidence and remaining work.

## Play locally

Use Node.js 22 or newer with npm. Network access is required for dependency installation; NexusEngine is pinned to an exact Git commit and lockfile integrity.

```sh
npm ci
npm run dev
```

Open the localhost URL printed by Vite. WebGL2 enables full graphics; browsers without it automatically use reduced Canvas graphics with the same story and controls. Web Audio supplies sound. The first click unlocks audio. Production output is generated by `npm run build` and served with `npm run preview`.

- Click a visible object or its bottom action card. `Look closer` changes the authored view.
- Read records, operate the mechanism, then choose a departure. Wrong attempts preserve essential evidence.
- `J`: journal; `I`: satchel; `M`: town map; `H`: progressive hint; `Esc`: close/pause.
- `Tab` or arrows moves focus; `Enter` selects. Gamepad navigation is implemented but needs physical-device validation.
- Menus and reading pause exposure. Puzzle controls remain under pressure. Gentle slows the deadline; Story removes it.
- Three save slots, autosave after meaningful changes, a prior-save recovery copy, and persistent settings.
- If browser storage is blocked or full, play continues with temporary session saves. A visible warning explains that closing or reloading loses that session; existing disk saves are not deliberately erased.
- Revisit known locations through the map before leaving the Well Chamber. Past choices stay fixed; missed observations can still be recovered.

## Validate

```sh
npm run content:check
npm test
npm run build
```

[Validation procedures](docs/validation/protocol.md) explain separate command, canvas, browser, audio, hardware, and desktop evidence. `npm run review:headless` needs a Vulkan adapter, including a supported CPU Vulkan implementation. It imports the actual game scene and UI provider. `npm run review` needs Chromium installed with `npx playwright install chromium` and the Vite server running; it uses mouse input and records a browser video.

## GitHub Pages

`.github/workflows/deploy.yml` runs on pushes to `main` and manual dispatch. It checks content, runs the scenario suite, builds, plays a complete route in Chromium with both WebGL and reduced graphics, and checks the production build with available storage, denied storage, and denied WebGL before uploading `dist` and deploying.

One-time setup: in this repository, choose **Settings → Pages → Build and deployment → Source → GitHub Actions**. GitHub's ordinary workflow token cannot enable a disabled Pages site. Then rerun the deployment job or push to `main`. The game is available at [Play Saint Orison](https://luminarylabs-publish.github.io/TheLastBellofSaintOrison/). See [GitHub's custom Pages workflow instructions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Browser screenshots, video and reports are retained in each deployment run's `browser-review` artifact for fourteen days. A failed browser check blocks publishing. Locally, after installing Chromium and building, run `node tools/review/ci.mjs` with ports 5173 and 4173 free.

## Desktop

```sh
npm run desktop
npm run desktop:package -- win32
```

The Electron shell uses a sandboxed renderer, isolated preload, local application protocol and per-user Chromium storage. Packaging is not proof of installation, Steamworks integration, Windows compatibility or save retention during upgrade. See [release gates](release/README.md).

## Modular production

The running game uses five project domains, sixteen Service Kits and fifteen location packages. Start with [CONTRIBUTING](CONTRIBUTING.md), [ownership](docs/architecture/ownership-ledger.md) and [extension points](docs/architecture/extension-points.md). Author room JSON, run `npm run content:build`, then `npm run validate:production`. `npm run author -- help` lists guarded generators. Existing saves migrate to domain snapshots. Google Drive synchronization is deferred.
